# Анализ предметной области — Variator2026

## Назначение системы

Платформа крауд-прогнозирования Variator демократизирует доступ к рынкам прогнозов через три ключевых принципа:

### 1️⃣ Демократизация доступа
- **Проблема:** Традиционные крипто-платформы требуют создания кошельков, покупки USDC, оплаты газа
- **Решение:** E-mail регистрация + платежные шлюзы (СБП, карты РФ) + виртуальный баланс
- **Результат:** Пользователи могут начать прогнозировать за 2 минуты

### 2️⃣ Механизм «Информационных ставок»
Пользователи голосуют активами, формируя объективную вероятность события:
- **Пример:** Если 80% средств на исход "Да", платформа показывает 80% → это оценка толпы
- **Ценность:** Нейтральный источник прогнозирования для аналитики, HR, принятия решений
- **Применение:** Компании могут использовать платформу как инструмент риск-менеджмента

### 3️⃣ Безопасная игровая среда
- **Без крипто-рисков:** Нет потери средств из-за ошибок контрактов или потери seed-фразы
- **Финансовое образование:** Пользователи развивают навыки вероятностного мышления в безопасных условиях

## Целевая аудитория

### 🎯 Сегмент 1: Аналитики и эксперты
- **Описание:** Люди с глубокими знаниями в экономике, политике, спорте, технологиях
- **Мотивация:** Проверить свои аналитические способности, капитализировать знания
- **Поведение:** Ищут нейтральные инструменты для прогнозирования, работают со статистикой
- **KPI:** Высокий win rate, долгие удержание

### 🎯 Сегмент 2: Начинающие пользователи
- **Описание:** Люди, начинающие осваивать вероятностное мышление и риск-менеджмент
- **Мотивация:** Развить навыки в безопасной среде, понять механику спроса-предложения
- **Поведение:** Ценят интуитивный интерфейс, прозрачные правила расчета
- **KPI:** Сложность операций ≤ 3 клика

### 🎯 Сегмент 3: Любители новостной повестки
- **Описание:** Активные потребители новостей в политике, спорте, шоу-бизе
- **Мотивация:** Проверить интуицию, сравнить мнение со средним рынком, развлечение
- **Поведение:** Быстро ищут актуальные события, отслеживают динамику котировок
- **KPI:** Еженедельная активность, среднее время сессии

### 🎯 Сегмент 4: Конкурентные пользователи
- **Описание:** Люди, мотивированные соревнованиями и лидербордами
- **Мотивация:** Попасть в топ, заработать социальный статус
- **Поведение:** Активные трейдеры, портфель из множества позиций
- **KPI:** Частота сделок, средний размер позиции

## Требования к системе

### Функциональные требования

#### 1. Регистрация и управление аккаунтом
- Email + пароль регистрация
- Двухфакторная аутентификация (опционально)
- Профиль пользователя с статистикой

#### 2. Управление виртуальным балансом
- Пополнение через платежные сервисы (СБП, карты РФ)
- Отображение баланса в реальном времени
- История финансовых операций

#### 3. Работа с портфелем событий
- Просмотр активных и скорозавершающихся рынков
- Поиск и фильтрация по категориям (Спорт, Политика, Шоу-бизес, Технологии)
- Сортировка по прибыльности, объему торговли, времени до закрытия

#### 4. Совершение сделок
- Покупка долей с выбором исхода и количества
- Блокировка покупки при недостаточном балансе
- Продажа долей обратно по текущей рыночной цене (идеальное исполнение)

#### 5. Динамическое ценообразование
- Автоматический пересчет котировок в процентах
- Принцип: чем больше купили "Да", тем дороже доля "Да"
- Формула: `price["Yes"] = total_yes / (total_yes + total_no) * 100%`

#### 6. Разрешение исходов
- Admin panel для закрытия события
- Выбор верного исхода администратором
- Автоматическое начисление выплат (1 токен = 1 доля помножено на множитель)

#### 7. История и аналитика
- Портфель текущих позиций
- История всех завершенных сделок (покупка, продажа, выплата)
- Статистика: win rate, средняя прибыль, убыток, ROI

#### 8. Уведомления
- Email о приближении дедлайна события
- Email о результате разрешения события
- Опциональная push-рассылка (для мобильных)

## Нефункциональные требования

### 🔧 Технические ограничения
- **Платформа:** Веб-приложение с адаптивной версткой (мобильные + десктоп)
- **Архитектура:** Микросервисы (Auth + Platform) с Database per Service
- **Коммуникация:** REST для клиента, gRPC для сервис-сервис, WebSocket для real-time

### 💰 Бизнес-требования
- **Легальность:** Функционирование в рамках ФЗ-152 (о персональных данных)
- **Виртуальность:** Использование виртуального баланса (без азартных игр)
- **Лимиты:** Максимум 100,000 руб на пополнение в месяц (для compliance)

### 🌍 Локализация
- **Язык:** Русский (основной), опция для английского
- **Часовой пояс:** UTC+3 (Москва)
- **Валюта:** RUB (рубли), опция BYN (Беларусь)
- **Форматы дат:** DD.MM.YYYY

### ♿ Доступность
- **Стандарт:** WCAG 2.1 Level AA
- **Контраст:** Не менее 4.5:1 для текста
- **Масштабирование:** 200% без потери функциональности

### ⚡ Производительность

| Метрика | Значение | Phase |
|---------|----------|-------|
| Время отклика (GET /markets/{id}/book) | ≤ 200ms | 1 |
| Обновление котировок | ≤ 1 сек | 1 |
| Выполнение сделки | ≤ 500ms | 1 |
| Одновременные пользователи | 100 | 1 |
| **Phase 2:** | | |
| Одновременные пользователи | 500-1000 | 2 |
| RPS (запросы в сек) | 1000 | 2 |

### 🔒 Надежность
- **ACID транзакции:** Соблюдение при всех операциях с балансом
- **Backup:** Ежедневное автоматическое копирование
- **SLA:** Uptime 99.9% (максимум 43 минуты downtime в месяц)
- **Recovery Time Objective (RTO):** < 15 минут

### 🛡️ Безопасность
- **Передача:** HTTPS/TLS 1.3
- **Хранение паролей:** bcrypt с cost factor 12 (не SHA-256!)
- **Аутентификация:** JWT с TTL 15 минут
- **Защита от IDOR:** Проверка владельца на каждой операции
- **Rate limiting:** 100 req/min на юзера, 1000 req/min на IP
- **SQL Injection:** Подготовленные запросы везде
- **CSRF:** SameSite=Strict на cookies

### 🎨 Удобство использования
- **Навигация:** 3 клика до покупки доли (максимум)
- **Мобильная адаптивность:** Корректное отображение на экранах 320px+
- **Онбординг:** Первая сделка за < 2 минут
- **Ошибки:** Понятные сообщения на русском, без технических кодов

3. Error rate: < 0.1% (< 1 ошибка на 1000 запросов)
4. Availability: 99.9% uptime в месяц
5. Data consistency: 100% ACID compliance на balance операциях

## Риски и mitigation

| Риск | Вероятность | Влияние | Mitigation |
|------|-------------|--------|-----------|
| **Race condition в matching** | Высокая | Высокое | Lua + Redis transactions |
| **Double spend** | Средняя | Критическое | Уникальные (user_id, event_id) + transaction версионирование |
| **Фронтенд lost updates** | Средняя | Среднее | Оптимистичные блокировки + retry logic |
| **DDoS** | Средняя | Среднее | Rate limiting + WAF (nginx) |
| **Insider threat** | Низкая | Критическое | Audit logging, 2FA для админов |
