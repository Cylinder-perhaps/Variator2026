## Описание ролей

### 🔧 ADMINISTRATOR

**Ответственность:** Завседневное управление платформой.

**Возможности:**
- ✅ Создание рынков (события)
- ✅ Разрешение исходов (settlement) → выплата призов победителям
- ✅ Управление модераторами (выдача/отзыв роли)
- ✅ Блокировка/разблокировка пользователей
- ✅ Просмотр audit logs всех операций

---

### 👨‍⚖️ MODERATOR

**Ответственность:** Контроль качества контента и соответствие правилам.

**Возможности:**
- ✅ Разрешение (settlement) рынков (наравне с Admin)
- ✅ Комментарии на равне с User
- ✅ Удаление спама в комментариях
- ✅ Блокировка нарушителей
- ✅ Просмотр жалоб (flags)

**Ограничения:**
- ❌ Не может создавать рынки
- ❌ Не может удалять модератора
- ❌ Только Admin может разблокировать

---

### 👤 USER

**Ответственность:** Участие в торговле и комментировании.

**Возможности:**
- ✅ Полный доступ к торговле (покупка/продажа)
- ✅ Просмотр своего портфеля и статистики
- ✅ Просмотр портфеля других (публичные данные)
- ✅ Комментирование рынков
- ✅ Установка флагов на контент (жалобы)

**Ограничения:**
- ❌ Не может управлять рынками
- ❌ Не может удалять чужие комментарии
- ❌ Не может блокировать пользователей

## Примеры сценариев

### Сценарий 1: Спам в комментариях

```
1. User_B пишет оскорбления под рынком
2. User_A нажимает "Flag" → создается жалоба
3. Moderator видит жалобу в админ-панели
4. Moderator удаляет комментарий User_B
5. Moderator блокирует User_B (временно)
6. System отправляет email User_B с уведомлением
```

---

### Сценарий 2: Неправильное разрешение рынка

```
1. Admin разверешает рынок неправильно (ошибка)
2. Moderator замечает ошибку, документирует в audit
3. Admin получает уведомление
4. Admin отменяет разрешение, выполняет корректно
5. Audit log сохраняет обе операции
```

---

### Сценарий 3: Новая платформа подъезжает на борт

```
1. Admin выбирает трудолюбивого User_C
2. Admin выдает ему роль Moderator (через API/Admin panel)
3. User_C получает пуш-уведомление "Вы назначены модератором"
4. User_C видит новую кнопку в интерфейсе "Модератор функции"
5. User_C начинает модерировать контент
```

## API реализация ролей

```go
// Примеры Authorization checks в коде

// 1. Только Admin может создувать рынки
func CreateMarket(user UserContext) -> Error {
    if user.Role != "admin" {
        return 403_Forbidden
    }
    // Создать рынок...
}

// 2. Admin И Moderator могут разрешить
func ResolveMarket(user UserContext) -> Error {
    if user.Role != "admin" && user.Role != "moderator" {
        return 403_Forbidden
    }
    // Разрешить рынок...
}

// 3. User может только создавать свои ордеры
func CreateOrder(user UserContext) -> Error {
    if user.Role != "user" && user.Role != "admin" && 
       user.Role != "moderator" {
        return 403_Forbidden
    }
    // Создать ордер для user.ID...
}
```
