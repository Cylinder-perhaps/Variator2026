## Назначение платформы

Variator — это платформа крауд-прогнозирования, которая демократизирует доступ к рынкам прогнозов через три ключевых принципа:

### 1️⃣ Демократизация доступа
- **Проблема:** Традиционные платформы требуют криптокошельков, USDC, оплаты газа
- **Решение:** E-mail регистрация + платежные шлюзы (СБП, карты РФ) + виртуальный баланс
- **Результат:** Пользователи начинают прогнозировать за 2 минуты

### 2️⃣ Механизм «Информационных ставок»
Пользователи голосуют активами, формируя объективную вероятность события:
- **Пример:** Если 80% средств на "Да", платформа показывает 80% вероятность
- **Ценность:** Нейтральный источник прогнозирования для аналитики
- **Применение:** Компании используют как инструмент риск-менеджмента

### 3️⃣ Безопасная игровая среда
- **Без крипто-рисков:** Нет потери средств из-за ошибок контрактов
- **Финансовое образование:** Развитие навыков вероятностного мышления
- **Полностью легально:** Функционирует в рамках законодательства РФ

## User Stories (Пользовательские сценарии)

### US-1: Быстрая регистрация

```
Как: Новый пользователь
Я хочу: Зарегистрироваться за 2 минуты без крипто-кошельков
Чтобы: Сразу начать торговать

Сценарий:
✓ Нажимаю "Регистрация"
✓ Вводу email и пароль
✓ Подтверждаю email (почта)
✓ Получаю стартовый баланс 100K RUB
✓ Готово! Вижу список рынков

AC (Acceptance Criteria):
- Регистрация ≤ 2 минуты
- Email подтверждение ≤ 30 сек
- Баланс зачислен сразу
```

---

### US-2: Фильтрация рынков

```
Как: Опытный пользователь (аналитик)
Я хочу: Видеть только высокий volume рынки, отсортированные по дате
Чтобы: Не тратить время на маленькие события

Сценарий:
✓ Перейду на /markets
✓ Выберу фильтр: category="Политика", sort="volume", minimal_volume=10M
✓ Вижу топ-10 событий по объему торговли
✓ Кликаю на интересующее событие → деталями

AC:
- Фильтрация работает за < 500ms
- Оптимальное кол-во результатов: 10-50 рынков
```

---

### US-3: Создание ордера с matching

```
Как: Пользователь (например, Иван-экономист)
Я хочу: Купить 100 долей YES за лучшую цену
Чтобы: Заработать когда событие разрешится в мою пользу

Сценарий:
✓ Нажимаю "Купить YES"
✓ Выбираю quantity=100
✓ Вижу текущую лучшую цену: 0.65 (65%)
✓ Нажимаю "Купить" (1 клик)
✓ Система делает matching в Redis
✓ Получаю обновленную цену (может быть 0.70)
✓ Баланс уменьшился на amount_paid
✓ Позиция добавлена в "Мой портфель"

AC:
- Ордер создан за < 500ms
- Matching произошел за < 100ms (Redis)
- Все данные consistent (баланс, позиция, ордер)
```

---

### US-4: Real-time котировки

```
Как: Активный трейдер
Я хочу: Видеть обновления цен в реальном времени
Чтобы: Не пропустить нужный момент для торговли

Сценарий:
✓ Открою /markets/market_123 (детали рынка)
✓ Система subscribe на WebSocket /ws/market_123
✓ Вижу текущую цену: YES 0.65
✓ Трейдер Федор делает ордер на YES
✓ Redis publish event на market_123
✓ Я в реальном времени вижу: YES 0.68 (цена изменилась!)
✓ Latency < 1 сек от события до обновления UI

AC:
- WebSocket connection ≤ 1 сек
- Обновление UI ≤ 1 сек после ордера
- Без polling, только push
```

---

### US-5: Просмотр портфеля и P&L

```
Как: Инвестор
Я хочу: Видеть мой портфель, прибыль/убыток по каждой позиции
Чтобы: Принимать решения о выходе или добавлении

Сценарий:
✓ Отройю "Мой портфель"
✓ Вижу таблицу с позициями:
  | Событие | Исход | Кол-во | Цена покупки | Текущая | P&L |
  | AGI? | YES | 100 | 0.70 | 0.75 | +500 RUB |
  | Выборы РФ | YES | 50 | 0.45 | 0.42 | -150 RUB |
✓ Сумма портфеля: 100K - 150 + 500 = 100,350 RUB
✓ ROI = +0.35%

AC:
- Загрузка портфеля ≤ 500ms
- Цены обновляются в реальном времени
- P&L пересчитывается правильно
```

---

### US-6: Разрешение рынка (Admin)

```
Как: Администратор
Я хочу: Закрыть событие и выбрать верный исход
Чтобы: Выплатить победителям

Сценарий:
✓ Открою админ-панель
✓ Найду закончившееся событие "Will AGI exist in 2026?"
✓ Видимо two buttons: "Yes" и "No"
✓ Выбираю "Yes" (исход получился верный)
✓ Нажимаю "Resolve"
✓ Система:
  - Обновляет status → "resolved"
  - Вычисляет winning_price = total_yes / (total_yes + total_no)
  - Выплачивает всем holders YES
  - Отправляет уведомления

AC:
- Только Admin может разрешать
- Разрешение необратимо (или с логом)
- Выплаты distributioned правильно
```

---

### US-7: История сделок и экспорт

```
Как: Трейдер (для налогов, анализа)
Я хочу: Видеть все мои исторические сделки + скачать CSV
Чтобы: Рассчитать налоги и провести анализ

Сценарий:
✓ Отройму "/my-trades"
✓ Вижу таблицу всех моих сделок за период
✓ Фильтрую по дате, события
✓ Нажимаю "Экспортировать CSV"
✓ Скачивается файл: trades_2026-04-13.csv

AC:
- История загружается за < 1 сек (с пагинацией)
- CSV содержит все необходимые поля
- Включены комиссии, налоги, P&L
```
