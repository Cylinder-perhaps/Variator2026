# 🌐 HTTP Status Codes

Полная матрица HTTP статус-кодов для всех API endpoints.

---

## Стандартные коды ответов

### ✅ 2xx — Успешные ответы

| Код | Описание | Когда используется |
|-----|---------|-------------------|
| **200 OK** | Запрос успешно обработан | GET, обновление данных |
| **201 Created** | Ресурс успешно создан | POST /api/orders, /api/markets |
| **204 No Content** | Успешно обработано | DELETE (без тела ответа) |

---

### ❌ 4xx — Ошибки клиента

| Код | Описание | Пример |
|-----|---------|--------|
| **400 Bad Request** | Неверный формат запроса | `{"quantity": "abc"}` вместо numbers |
| **401 Unauthorized** | Требуется аутентификация | Нет JWT токена или истек |
| **402 Payment Required** | Недостаточно средств | Баланс < требуемой суммы |
| **403 Forbidden** | Недостаточно прав | User пытается создать рынок |
| **404 Not Found** | Ресурс не найден | Рынок, ордер, пользователь |
| **409 Conflict** | Конфликт состояния | Рынок уже разрешен (idempotency) |
| **422 Unprocessable Entity** | Логические ошибки | Deadline в прошлом |
| **429 Too Many Requests** | Превышен rate limit | >10 логинов за 15 минут |

---

### 🔴 5xx — Ошибки сервера

| Код | Описание | Когда происходит |
|-----|---------|------------------|
| **500 Internal Server Error** | Непредвиденная ошибка | Crash в обработчике, exception |
| **502 Bad Gateway** | Сервис недоступен | Timeout, микросервис crashed |
| **503 Service Unavailable** | Временная недоступность | Maintenance, перезагрузка |

## Матрица по Endpoints

### 🔐 AUTH Endpoints

#### POST /api/auth/dummyLogin (MVP)
```
200 ✅  Demo аккаунт создан → JWT + Refresh token
400 ❌  Неверные параметры demo
500 ❌  Ошибка при создании demo аккаунта
```

#### POST /api/auth/register (v2)
```
201 ✅  Пользователь создан → JWT
400 ❌  Email невалиден, пароль < 8 символов
409 ❌  Email уже зарегистрирован
422 ❌  Пароль слишком слабый (нет букв, цифр, символов)
500 ❌  Ошибка хеширования bcrypt
```

#### POST /api/auth/login (v2)
```
200 ✅  Успешный вход → JWT + Refresh token
400 ❌  Неверный JSON
401 ❌  Email не найден ИЛИ пароль неверен
429 ❌  Слишком много попыток входа (>10 за 15 мин)
500 ❌  Ошибка БД
```

#### POST /api/auth/refresh (v2)
```
200 ✅  Новый JWT выдан
401 ❌  Refresh токен истек (> 30 дней)
403 ❌  Refresh токен отозван (был logout)
500 ❌  Ошибка выдачи токена
```

#### POST /api/auth/logout (v2)
```
204 ✅  Выход успешен (сессия инвалидирована)
401 ❌  Не авторизован
500 ❌  Ошибка инвалидации сессии
```

## Best Practices

### Idempotency

```
DELETE /api/orders/{id}
- Первый вызов: 204 No Content (отменено)
- Второй вызов (того же ID): 204 No Content (уже было отменено)
- Результат: Один ордер отменен один раз (не дважды)

Почему? Чтобы клиент мог повторить запрос при network timeout
```

### Rate Limiting

```
429 Too Many Requests

Headers возвращаемые:
X-RateLimit-Limit: 100        (лимит за период)
X-RateLimit-Remaining: 42     (осталось запросов)
X-RateLimit-Reset: 1681234567 (когда сбросится)

Пример: >10 логинов за 15 минут → 429 на 15 минут
```

### Error Response Format

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Баланс недостаточен для этой операции",
    "details": {
      "required": 50000,
      "available": 32000
    }
  }
}
```
